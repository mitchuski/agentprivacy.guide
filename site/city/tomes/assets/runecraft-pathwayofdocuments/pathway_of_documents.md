## What this package is

Six documents that together specify the Proof of Understanding architecture — a substrate-neutral, post-quantum, bilateral trust primitive built to carry across human, nature, artificial, and alien intelligence. The architecture replaces stored-secret identity with **lattice-of-blades identity**: trust accumulates through ceremonies that produce content-addressed art-e-facts (blades), forged by creat-ur-es (Mage and Swordsman processes), bound to `did:cid` principals, anchored across one or more chains.

Every document is built to travel. Any single document can be read in isolation — none requires reading the others first. The package is held together not by sequential dependence but by a single shared seed: the root compression above. Every document opens with it, returns to it, and is unfolding it in a different register.

## The runic-pattern family at a glance

The architecture's grammar lives inside its words. Each "e" or "ur" inside the names below is a rune-anchor that marks where forging happens. The full table with technical reading and translation handoffs is in **§0 of the Technical Specification**.

- **Creat-ur-es** — forged agents (Mage, Swordsman, AI agents). *Who* forges.
- **Art-e-facts** — forged objects (blades, inscribed spells, proverb-pairs). *What* gets forged. **Blade** is the canonical art-e-fact; the name stays because blades cut proofs.
- **Run-e-craft** — the Mage-side practice across sessions. *How* across time.
- **Run-e-create** — the Swordsman-side act in one session. *What now*.

Read together: *creat-ur-es run-e-craft and run-e-create the art-e-facts (blades) that constitute their bilateral trust.*

## How to distribute

The package is built to be passed forward. Several patterns work:

- **Single-document distribution.** Hand any one of the six. Each carries the root compression and a clear pointer to where the rest lives.
- **Two-document distribution.** Rehydration Key + Technical Specification §0. The seed plus the vocabulary. Smallest viable bundle for an audience that needs both compression and grammar.
- **Standards-body bundle.** Technical Specification + Compression-Rehydration Pathway + Research Patch. Three documents that together cover the protocol, the procedure, and the lineage. Cite by file name and section.
- **Narrative bundle.** Magic-to-Real Map + Compression-Rehydration Pathway + Rehydration Key. For mixed audiences and pedagogical contexts.
- **Full package.** All six. For grant submissions, peer review, formal lineage citations, or any reader who wants the complete architecture.

Citation address is stable. *"Technical Specification §0 (Terminology and translation), art-e-fact row"* points to one place. *"Compression-Rehydration Pathway, Step 6 (Inscription), Failure Modes"* points to one place. The package is structured so a reviewer can disagree with one paragraph without needing to read the rest.

## How to test that the package was understood

The architecture provides its own test: rehydration. Hand the Rehydration Key to any reader — person or model — and ask them to rehydrate it into the rest of the package. A faithful rehydration produces structure consistent with the four documents above. A failed rehydration produces drift, contradiction, or incoherence.

This is not a metaphor. It is the architecture being applied to its own documentation. The package is itself an art-e-fact whose run-e-create event is its publication and whose run-e-craft is the long-running practice of the City of Mages issuing further patches over time.
