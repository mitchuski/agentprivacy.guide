Star core artefact and moving ceiling

Design proposal, 2026-09-08. Recorded from the First Person's direction; not an implemented feature or a new mathematical claim.

The core PFP

Allow the keeper to select an image or information artefact as the central orb inside the paired Star tetrahedra. The core is a recognisable face for what is carried. A surrounding temporal ring can express the existing moving-ceiling model. Clicking reveals the artefact reading and controls; the compact City/extension view stays a small bottom-right orb, an interaction approved by the keeper.

Fit with the existing model

Extend PLAN_KEY_EVOLUTION_MEASURED_GEOMETRY_2026-06-10.md and its chosen/derived/measured/proven progression. Preserve SHAPE(key) as a pure, versioned function of canonical content. Treat time as a separate VIEW(key, modelVersion, observationTime, context). A changing view must not silently change key bytes or commitments.

The live Star previously displayed R(T), T* and the boundary condition R(t) < 1. The currently inspected local star/index.html retains the boundary wording but does not contain that ceiling badge implementation. Pin and reconcile the actual source from the keeper's other work before selecting a decay curve, units, coefficients or threshold. Determine whether the quantity represents value retention, exposure growth or another measure. Do not equate R(T) with image opacity by assumption.

Proposed data contract

An optional versioned coreArtefact field references the chosen artefact, alternative text, provenance, display policy and optional model reference. Original bytes remain in local/VTA custody. References and commitments can reveal relationships too, so release them deliberately. Round-trip new fields without replacing existing journey content.

The derived view contains only an approved thumbnail or placeholder, model/version, as-of time, source-defined parameters and a typed state: illustrative, observed, modelled, stale or unavailable. Credential active/expired/revoked status is separate. Modelled decay neither revokes credentials nor deletes data, makes copies unrecoverable or proves privacy. New evidence creates a dated observation rather than erasing historical exposure.

Visual and interaction rules

Clip the selected image within the central sphere/disc; use an artefact glyph when no image is shared. Place the temporal ring around the core, structural tetrahedron edges visibly around it, and decorative halos behind. Separate core selection from drag-to-orbit. Keep the panel in its own HTML stacking layer. Provide keyboard access, reduced motion and a paused/as-of view. State the quantity in text when expanded; fading alone cannot carry its meaning.

Start with local raster selection, file/dimension limits and a metadata-stripped thumbnail. Never automatically fetch arbitrary key-supplied image URLs. Cross-site image release is an explicit disclosure. Removing or revoking display prevents future release but cannot retract previously shared copies.

Implementation sequence

  1. Pin the active ceiling source and establish source-backed temporal semantics and fixtures.
  2. Add core selection to Soulbis Star; verify JSON/PNG round-trip, unknown-field preservation and stable key identity while display time advances.
  3. Add the same compact view to the existing extension. Explain selection and disclosure there. Store originals privately and clear context-specific imagery when the audience changes.
  4. Feed an approved projection into the City's accepted floating orb through an authenticated, origin-bound extension connection. Use the same model contract in agentprivacy and Spellweb with each site's own permitted perspective.
  5. Connect actual VRC/MyTerms outcomes and encounter receipts via city_mage. Append approved observations to the private journey. Never form trust edges from animation, time passage or image choice alone.

Acceptance gate

Test the same artefact across observation times with key bytes unchanged; two artefacts at the same time; unknown models, unavailable images, stale observations, expired credentials and revoked display independently. Verify agreement between compact and expanded values, image privacy across context switches, occlusion, keyboard interaction, reduced motion and hostile image references.

The current City bottom-right orb supports palette import only. Core image selection, temporal measurement rendering and authenticated extension sharing remain proposed. A visual study may precede model reconciliation, but must be labelled illustrative.
